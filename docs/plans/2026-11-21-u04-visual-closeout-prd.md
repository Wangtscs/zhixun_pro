# PRD：运维台遗留表面收口与双主题交互回归（U04）

> 任务编号：U04（承接 U01–U03 的统一工业作业视觉）
> 分支：`feat/u01-u03-refined-operations`
> 状态：待接缝确认与发布

## Problem Statement

巡检与派单人员已经在使用统一后的精密作业台，但浅色主题下仍夹着上一版遗留的深色、渐变和高饱和表面：个人设置里的头像与图标块像一块块贴上去的深色标签，“换绑”看起来像一个没有填完的输入框；登录设备用手机图标表示电脑、用错配图形表示终端；账户菜单展开后是一组深色嵌套角色列表，字号和行高与周围菜单不一致；审计日志的日期筛选是一个突兀的深色胶囊，文案“全部日期”与实际含义对不上；空间态势的隧道底图、节点标签底色和引脚填充仍停留在深色霓虹风格；实时告警流卡片使用深色底，且“派单”按钮用绝对定位压在标题时间上，窗口一窄就互相挤压。

这些问题让操作员难以判断哪些面是可操作控件、哪些是状态信息，也破坏了同一屏内的比较与阅读节奏。作业台的核心任务是快速看清告警、工单和证据；遗留表面制造的是视觉噪声，而不是信息。

## Solution

把 U01 建立的单一作业台语义面推广到所有遗留区域：中性抬升面、细线边界、唯一强调色、平面图标块，深色仅作为显式主题而不是默认装饰。个人设置回到“身份 + 操作”的平面阅读顺序；登录设备按真实终端类型显示显示器或手机图形；账户菜单改为与系统一致的浅色菜单，角色以扁平分组呈现；审计日期筛选与相邻下拉同高、同字号、同边界，默认文案改为“全部日期”；空间态势使用浅色工程图面，节点引脚改为浅色填充加语义描边，节点名称去掉白色底片；实时告警流使用中性卡片配左侧严重度条，“派单”回到正常流式布局，在窄宽度下不与时间重叠；品牌标记改为管廊断面图形。

所有调整只改变呈现、排版和少量模板结构，不新增业务实体，不改接口、状态机、权限和数据库，不引入新的前端依赖。

## User Stories

1. 作为巡检人员，我希望浅色主题下所有面板都属于同一套中性台面，以便一眼区分“可操作区域”和“状态信息”。
2. 作为巡检人员，我希望任何区域都不再出现深色渐变或发光装饰，以免误以为那是独立的应用或警告。
3. 作为巡检人员，我希望个人设置的头像使用平面色块和细线边界，以便身份信息看起来稳定、可读，而不是一块深色装饰。
4. 作为巡检人员，我希望头像与姓名、角色、区域信息按从左到右的顺序对齐，以便快速确认“我是谁、我在哪个区域”。
5. 作为巡检人员，我希望“换绑”作为内联文字操作紧跟在手机号后面，以便知道它作用于哪一行，而不是像未填写的输入框。
6. 作为巡检人员，我希望“换绑”在禁用、加载和失败时保持文字操作的外观并给出状态，以便区分“不能点”和“点了没反应”。
7. 作为巡检人员，我希望手机号输入框与“换绑”在同一行内自适应，以便在窄窗口中不互相覆盖。
8. 作为巡检人员，我希望登录设备列表中的每个设备使用中性背景的平面图标块，以便视觉焦点落在设备名称和状态上。
9. 作为巡检人员，我希望电脑显示显示器图形、手机和平板显示手机图形，以便不必读平台字符串就能识别终端类型。
10. 作为巡检人员，我希望平台信息缺失或无法识别时回退为通用桌面图形，而不是显示错误图标或空白。
11. 作为巡检人员，我希望登录设备、安全设置和修改密码的图标块保持一致的尺寸、边界和灰度，以便设置页看起来是一个整体。
12. 作为巡检人员，我希望安全设置中的修改密码入口使用与含义匹配的图标，以便在列表中快速定位。
13. 作为巡检人员，我希望账户下拉菜单使用与页面一致的浅色表面、边界和阴影，以便展开时不会突然变成另一个产品。
14. 作为巡检人员，我希望账户菜单的每一项使用 14px 正文、足够的行高和悬停/按下反馈，以便可点击区域清楚且不拥挤。
15. 作为巡检人员，我希望角色切换以扁平分组展示，当前角色用强调色和圆点标记，以便知道当前生效的是哪个身份。
16. 作为巡检人员，我希望展开角色分组时箭头方向随状态变化，并带有正确的展开语义，以便键盘和读屏用户也能理解。
17. 作为巡检人员，我希望只有退出登录使用危险色，且仅在该项悬停时出现淡红底，以免整个菜单被红色污染。
18. 作为巡检人员，我希望账户菜单支持键盘聚焦、回车触发和清晰的焦点环，以便不用鼠标也能完成切换角色和退出。
19. 作为审计人员，我希望日期筛选与相邻筛选控件同高、同字号、同边界，以便工具栏看起来是一组可比较的控件。
20. 作为审计人员，我希望未选择日期时显示“全部日期”，以便知道当前没有日期限制。
21. 作为审计人员，我希望选择了起始或结束日期后，摘要显示“起 — 止”并对缺失端显示“不限”，以便明确当前范围。
22. 作为审计人员，我希望日期弹层的输入框、标签和按钮使用同一套字号与边界，以便在弹层内继续完成筛选。
23. 作为审计人员，我希望日期筛选在深色主题下保持同样的层级关系，而不是变成高饱和色块。
24. 作为监控人员，我希望空间态势的隧道底图使用浅色工程图面，以便与周围的节点和告警信息处于同一视觉层。
25. 作为监控人员，我希望隧道网格线足够淡，以便提供尺度感但不与节点争夺注意力。
26. 作为监控人员，我希望隧道拱线和路面使用语义边界与中性填充，以便看懂结构而不被装饰性光效干扰。
27. 作为监控人员，我希望节点引脚使用浅色填充和语义描边，正常、告警、离线分别可辨，以便快速定位异常点。
28. 作为监控人员，我希望告警节点带有克制的环形提示，离线节点降低对比，而不是所有节点都发光。
29. 作为监控人员，我希望节点名称直接显示在引脚下方且没有白色底片，以便文字与背景融为一体。
30. 作为监控人员，我希望节点名称在悬停或键盘聚焦时变为强调色并出现焦点环，以便确认当前指向的节点。
31. 作为监控人员，我希望节点名称字号不小于辅助文字下限，以便在监控距离下仍能读清。
32. 作为监控人员，我希望图例中的名称和数量使用一致的字号和间距，以便横向比较各状态的节点数。
33. 作为监控人员，我希望节点悬浮提示使用浅色表面、细线边界和正常文字色，以便在浅色底图上仍然清楚。
34. 作为监控人员，我希望实时告警卡片使用中性抬升面和左侧严重度条，以便一眼看出哪条更紧急。
35. 作为监控人员，我希望普通告警与高严重度告警只通过左侧条和语义色区分，而不是整卡染色，以便长时间浏览不疲劳。
36. 作为监控人员，我希望与当前节点关联的告警卡片使用强调色底和边界，以便知道它对应图上的哪个点。
37. 作为监控人员，我希望告警标题、时间、原因和严重度使用稳定的 14/12/13px 层级，以便快速扫读而不是逐字阅读。
38. 作为监控人员，我希望“派单”按钮位于卡片底部的正常文档流中，以便在任何窗口宽度下都不压住标题或时间。
39. 作为监控人员，我希望在窄窗口中告警底部信息可以换行，而不是让按钮被挤出卡片。
40. 作为监控人员，我希望点击“派单”只打开派单流程，不会误触为选中或跳转告警，以便保持原有交互。
41. 作为所有用户，我希望品牌标记是管廊断面图形，并与导航文字基线对齐，以便它表达业务而不是通用装饰。
42. 作为所有用户，我希望品牌标记继承当前文字颜色，以便在深浅主题和不同背景上都保持一致。
43. 作为所有用户，我希望左侧导航的图标列、文字基线和激活强调条对齐，以便快速定位当前模块。
44. 作为所有用户，我希望首次访问默认浅色，已显式选择深色的用户继续使用深色，以便不覆盖个人偏好。
45. 作为所有用户，我希望深浅主题共用同一套业务语义色，以便告警、成功、离线和危险在两套主题下含义不变。
46. 作为所有用户，我希望正文不小于 14px、辅助文字不小于 12px、控件圆角控制在 5–8px，以便长时间作业时阅读舒适。
47. 作为所有用户，我希望所有可交互元素都有可见的悬停、按下和焦点状态，以便知道操作是否被接收。
48. 作为所有用户，我希望在窄窗口、浏览器缩放和长设备名称下不出现文字截断、按钮重叠或横向滚动。
49. 作为所有用户，我希望空列表、加载失败、权限不足和演示数据状态仍然清晰可见，不被视觉收口掩盖。
50. 作为运维负责人，我希望本次收口不改变派单、告警、工单、巡检的权限、状态和写入结果，以便视觉调整不引入业务回归。
51. 作为运维负责人，我希望验证记录明确区分“代码/构建通过”和“真实界面已验收”，以便不把静态检查当成交互验收。
52. 作为后续维护者，我希望所有遗留表面通过同一套设计令牌覆盖，而不是继续堆叠页面级特例，以便下一次主题调整只改一处。

## Implementation Decisions

- **模块范围**：Admin 网页的作业台主题层、个人设置、账户菜单、审计日志工具栏、空间态势、实时告警流、共享图标与品牌标记。Java 接口、移动网关、鸿蒙端和硬件桥不在本次改动内。
- **单一语义面**：所有遗留深色/渐变表面改为中性抬升面 + 细线边界；强调色只用于选中、当前、链接和主操作；危险色只用于退出与破坏性操作；告警/成功/离线使用各自语义令牌。
- **设计令牌契约**：沿用并补齐表面、抬升、悬停、按下、边界、控件边界、正文、辅助、强调、危险、警告、离线、成功、圆角等令牌。业务组件只消费令牌，不直接写页面级色值。
- **层叠策略**：遗留样式来自主题覆盖和通用元素选择器，收口规则统一挂在作业台根作用域下，以稳定优先级覆盖旧规则；不使用 `!important` 堆叠，也不删除仍被其他页面使用的旧规则。
- **平面化**：移除头像、图标块、菜单、日期控件、隧道底图和告警卡上的渐变、背景图、发光阴影和深色底；保留必要的 1px 边界和低透明度投影表达层级。
- **个人设置**：身份区改为头像 + 文本纵向排列的平面布局；头像使用强调色文字与浅强调底；手机号与“换绑”同一行自适应；“换绑”为内联文字按钮，保留禁用、加载、失败状态。
- **设备图标**：共享图标组件新增显示器与手机两个字形；设置页根据平台字符串选择手机字形，其余回退显示器；图标块统一为中性底、细线边界和小尺寸。
- **账户菜单**：菜单宽度、内边距、行高和字号统一；角色分组改为透明扁平分组，当前角色用强调色与圆点；展开按钮维护 `aria-expanded`；退出登录仅使用危险色。
- **审计日期筛选**：日期控件改为与相邻下拉一致的 40px 高、14px 摘要字号、表面底与细线边界；摘要默认“全部日期”，有范围时显示“起 — 止”；弹层输入与按钮沿用令牌。
- **空间态势**：隧道容器改为抬升面，网格使用低透明度边界色；拱线与路面使用边界/强调底；引脚使用表面填充加语义描边，告警增加淡色环，离线降低对比；节点名称去掉底片，使用正文色与等宽数字。
- **实时告警流**：卡片使用抬升面与左侧 3px 严重度条；关联态使用强调底与强调边界；“派单”改为静态定位并置于底部正常流，底部信息允许换行；保持点击派单不触发卡片选中。
- **品牌标记**：改用管廊断面意象（外层拱、内层衬砌、地面线与轨道刻度），统一 `currentColor` 和固定视框，不依赖主题背景图。
- **主题行为**：无本机偏好时默认浅色；显式深浅选择继续生效；读取失败回退可用默认值；两套主题共享业务语义。
- **可访问性**：可交互元素提供 `focus-visible` 焦点环；展开状态有语义；辅助文字不小于 12px；正文 14–15px；业务表格行高保持 52–56px；不依赖颜色单一通道表达严重度。
- **交互保持**：不新增写入路径，不改请求、授权、轮询、状态机和错误保护；演示、过期、失权、未知写入状态继续可见。
- **工程约束**：不引入前端依赖；不修改构建配置；不改接口契约；不生成演示数据写入真实库；不启动外部浏览器窗口或鸿蒙虚拟机。

## Testing Decisions

- **好测试的标准**：断言用户可观察的外部行为——渲染后的颜色关系、尺寸一致性、元素是否重叠、交互是否可用、状态语义是否正确；不断言类名、DOM 层级或具体十六进制色值本身。
- **唯一接缝**：复用现有浏览器冒烟入口，在“渲染后的 Admin 页面”这一层验证工作台、审计日志和个人设置三个入口。新增一个视觉契约规格，不按组件各建一套测试。
- **接缝运行方式**：视觉契约规格必须显式指定隔离的预览地址，禁止指向开发者正在使用的 5173；允许无头运行，禁止自动弹出可见 Edge/Chrome 窗口。若执行环境不允许无头浏览器自动化，则用同一份断言清单在 Codex 内置浏览器中手动核对，并如实标记哪些项未验收。
- **现有先例**：纯逻辑模块使用项目内 `node:test`；页面级验证使用现有 Playwright 冒烟脚本（显式基址、独立回环端口、产物写入验证目录）。视觉契约沿用同一启动与产物约定，不新建第二套浏览器工具链。
- **自动断言范围**：
  - 个人设置：头像无渐变背景图、图标块为中性底、设备图标与平台匹配、“换绑”与手机号输入无矩形相交、禁用态仍可辨认。
  - 账户菜单：菜单为浅色表面、角色分组非深色底、当前角色有强调标记、退出项仅在悬停时出现危险底、展开按钮语义随状态变化。
  - 审计日期：与相邻下拉高度一致、摘要默认“全部日期”、有范围时显示“起 — 止”、弹层打开后边界变为强调色。
  - 空间态势：隧道容器为抬升面、引脚为表面填充、告警与离线描边不同、节点名称无背景色且字号达标、悬停/聚焦出现强调色与焦点环。
  - 实时告警：卡片为抬升面、左侧条随严重度变化、关联态为强调底、“派单”与标题时间矩形不相交、窄宽度下按钮仍在卡片内。
  - 全局：浅色/深色切换后上述语义保持；正文与辅助字号下限；控件圆角范围；焦点环可见；无横向溢出。
- **手动交互清单**：切换个人设置各标签页、展开/收起角色、打开/关闭日期弹层并清空范围、悬停与键盘遍历节点、点击派单并确认未触发告警选中、窄窗口下查看告警底部换行、刷新后主题偏好保持。
- **证据记录**：类型检查、生产构建、视觉契约结果和手动核对结果分别记录；构建通过不能替代界面验收；内置信箱尺寸不可用时，明确记录“像素级验收未完成”。
- **回归保护**：视觉契约只读取和点击，不写入业务数据；不依赖真实账号的写操作；使用演示或隔离环境验证派单入口。

## Out of Scope

- 任何业务实体、接口契约、状态机、权限模型、数据库结构和迁移。
- Java 后端、移动网关、鸿蒙端、硬件桥和真实设备联调。
- 新增页面、功能流程、图表能力或前端依赖。
- 登录页、全局字体替换和品牌视觉系统的进一步扩展（登录页统一已另行完成）。
- 响应式重做；本次只保证现有断点下不重叠、不截断。
