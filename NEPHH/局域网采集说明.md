# 初赛局域网网页采集

2026-11-17：桌面 NEPHH 采集桥已增加 Wi-Fi HTTP 模式。ESP32 无需通过串口传输数据，仍需独立供电；电脑与设备须处于可互通的局域网。

链路：ESP32 HTTP GET → 电脑采集桥 → Vite网页代理 → 实机面板。当前设备地址 http://10.108.40.56，接口 /api/v1/telemetry。采集桥每次请求超时2.5秒，完成后约1.5秒再读；设备相同帧号不会刷新接收时间，超过6.5秒无新帧则过期。断网时清除当前值，不回退为串口或模拟数据。

桌面配置文件 `C:/Users/Stary/Desktop/NEPHH/.nephh-runtime/hardware-source.json`：

```json
{"deviceUrl":"http://10.108.40.56","deviceId":"ZX-S3-01"}
```

启动器仍运行原tools/hardware-bridge.cjs，它会读取该配置并选择Wi-Fi模式。也可显式运行 `node tools/hardware-bridge.cjs --url http://10.108.40.56`。设备DHCP地址改变时，更新deviceUrl并重启采集桥。删除配置或移除deviceUrl可在重启后恢复原USB模式。

网页显示“Wi-Fi 已连接”、设备地址及电气quality。INA226故障时V/A/W显示空值和真实错误状态，不编造数值。温湿度来源measurement，甲烷来源simulation。旧兼容application标识仍为nephh-usb-bridge，新增transport=WIFI_HTTP用于区分链路。

有真实登录并选择节点后，可沿用“开始上报到后端”；生成的候选业务报文只包含实测温湿度，source=ESP32_DHT11_WIFI。接入时未主动发送业务POST，本轮无线入库及数据库回读尚未新增验收。模拟甲烷和电气数据仍只预览。

后端Java源码和数据库表结构未修改。此模式完成局域网读取与网页预览，不代表ESP32主动POST或复赛腾讯云部署已完成。

新增脚本tools/wifi-frame.cjs校验schema、设备ID、boot_id/sequence、采样时间、单位、来源与数值范围；重启可重新接收帧序号。4项无线解析测试及8项串口回归通过，网页类型检查/Vite构建通过。旧桌面文件备份位于.nephh-runtime/backups/wifi-ina-20261117。
