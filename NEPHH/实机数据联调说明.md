# 实机数据联调

本次临时联调链路为 ESP32 → USB 串口 → 电脑采集桥 → 网页 → 现有 Java 业务后端 → MySQL → 网页。

电脑保持原有网络连接。没有更改固件、烧录或切换 ESP32 热点。正式 ESP32 直连腾讯云方案不由这次临时转发替代。

## 使用

1. 将 ESP32 的 USB 转串口连接到电脑。采集桥自动识别唯一一块 CH340，串口变化后会重新识别；存在多块 CH340 时须手动指定。
2. 关闭占用该串口的 Arduino 串口监视器，然后双击桌面“启动智巡管廊.cmd”。
3. 网页右下角会显示“采集节点实时数据”，约两秒更新一帧。温湿度为实测，甲烷为模拟 %LEL（旧固件输入由采集桥换算）；串口未输出 MQ-4 原始电压时，不把它假装成已采集数据。
4. 如需真正写入业务后端，使用团队已有管理员或值班长账号登录，选择用于联调的已有节点，再点“开始上报到后端”。独立演示环境不会写业务数据库。
5. 成功后会显示节点、序号和“已入库并回读核对”的温湿度。原有节点列表按其现有周期刷新，也可以手动刷新。
6. 点“停止上报”或关闭网页即可停止业务写入；采集桥仍继续只读串口。设备断开、采集报错或超过6.5秒无新帧时，停止提供可上报数据，不补零或重报缓存。

## 数据约定

- 当前业务上报仅有 temperature 与 humidity，source 为 ESP32_DHT11_USB。
- 甲烷模拟值统一保留 %LEL 和 simulation，仍仅预览，不写入业务 methane 字段；单位相同不代表实测来源。
- 固件简洁串口没有 UTC 时间和原始序号；messageId 使用电脑采集会话 UUID 与帧号。collectedAt 是电脑收到该帧的时间，采集桥明确标注 timeQuality=receiver_timestamp，不能冒充设备已校时。
- 写入后按 messageId 回查现有业务历史，核对数值和来源。鉴权继续使用现有网页登录会话，不创建账号、不绕过鉴权，不向固件写管理员 token。
- 尚未选择接收节点或缺少真实登录时，只预览串口数据，不向业务数据库写入。

若连接多块 CH340 或需要使用其他 USB 串口，可在停止采集桥后运行 `node tools/hardware-bridge.cjs --port COM11`。当前快速启动默认自动识别唯一的 CH340，不固定 COM 号。

此组件使用 Vite 开发代理进行本机联调；生产部署需要另行配置受控设备接入和业务鉴权，不能仅复制静态 dist 就期待电脑 USB 采集桥继续可用。
