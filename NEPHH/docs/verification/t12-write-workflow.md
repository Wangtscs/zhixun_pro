# T12 写入反馈与派单草稿集成

状态：代码已接入，定向行为测试和 Vue 类型检查通过。用户要求本轮继续代码/API，不切回预览、不启动外部浏览器或虚拟机；真实浏览器交互、401重新登录及网络故障注入尚未验收，T12不能据此标为完整完成。

## 本轮改动

- `Workspace.vue` 接入现有 `dispatch-draft.ts`。只将工单ID、人员ID、优先级、截止时间、备注传入白名单存储；同一标签页最长一小时。同账号必须先成功获取服务器 identity 才恢复。逐个稳定 `/orders/{id}` 检查 DRAFT、读取权限及区域，再读取最新 `/users` 筛除禁用或失去共同区域授权的人选；不依赖最近500条工单列表，不自动提交。存储失败给出明确提示。
- 取消、确认派单成功、主动退出清除派单草稿。401和自动空闲退出保留未完成输入；认证模块不因401清草稿。已失效、已派发、不可访问或区域无法核实的旧工单不恢复为可提交表单。暂时读取失败可手动重新核对草稿。
- `write-workflow.ts` 将写请求、确认后关闭表单、后续读取分开。写成功先关闭，再刷新；刷新失败明确提示已提交，保留刷新入口，不把同一表单重新开放。
- 使用请求层 `outcomeUnknown`。超时、响应丢失等未知结果锁定当前操作，禁用编辑、取消和再次提交，只允许 GET 核对。工单派发、调期及 accept/start/submit/reject/approve/cancel 要求新 actor/action/note 事件和目标状态；派发还核对所有工单的人员、优先级、期限，提交结果还核对正文及读数。未变化的 GET 或核对失败都不能解除锁定，更不会自动重发 POST。
- 未知工单写入另存一个白名单安全锁：仅 actor ID、操作类别、工单ID、旧事件最大ID及核对所需可编辑字段。不存 token、密码、人员/工单整对象。刷新或同账号重新登录优先恢复锁并 GET 核对；安全锁不按普通草稿TTL自动解锁，确认成功后清除。其他账号不得读取旧账号内容。
- 忙时防连点、防关闭；未知时保留表单及输入。Escape在捕获阶段只处理最上层弹层，避免告警子弹层先关闭后再冒泡关闭另一层；忙时或未知结果不能关闭写表单。保留只读模式、执行人权限和管理员不可复核本人主责工单等规则。
- 修正消息页已读消息不能再次查看关联详情的回归：有告警/工单关联可反复查看，仅未读消息写入已读状态；无关联消息保持标已读操作。

## 验收边界

- 浏览器验证待办：提交中关闭/双击/Escape、写成功后 GET 失败、POST 已提交但响应丢失、401同账号恢复及权限变更、批量部分响应与全部事务状态回读。单测与类型检查不替代这些交互验收。
- 无稳定结果编号的其他表单（例如新建用户/新建工单）若写入未知，本页保持锁定，提示管理员核实；本轮不伪造 GET 成功证据，也不承诺这类表单可跨刷新恢复安全锁。存储不可用时同样明确提示保持页面核实。
- 工单 GET 仍不足以证明结果时持续锁定，不能凭一次“当前没变化”判失败并放开重试。没有后端幂等键及写入状态查询契约，本轮不提供自动补提。
- SHA和推送由主代理完成审查后补记；本代理未暂存、提交或推送。
