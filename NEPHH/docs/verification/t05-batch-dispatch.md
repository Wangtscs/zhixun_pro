# T05 批量派单的共同授权与失败反馈

状态：实现与隔离验证通过，待主代理审查提交。

## 实现

- 所选工单ID逐张解析当前列表记录与区域；缺少记录、缺少区域、重复或非法ID、超过100单以及REVIEW/COMPLETED/CANCELLED等不可派发状态均失败关闭。
- 候选必须同时覆盖所有所选工单区域；不能从第一张工单继承候选范围。
- 批量入口独立构建空选择草稿，选择和提交时重新验证共同授权；1至2人及服务器最终权限/状态检查不变。
- 没有共同候选时提示按区域拆批，提交按钮禁用。
- 服务端业务失败保持抽屉、人员和备注，不显示成功提示。服务器现有批量事务不变。
- 没有修改公共网络请求层。401仍清会话并转登录，同账号草稿恢复及重新鉴权统一留待T12；不宣称本任务已实现401输入恢复。

## 验证

环境：Node24.22.3、可见Edge146、Vite5174、显式verification-mode的local/H2 API18081。业务写入脚本同时要求loopback、双方健康隔离标记、显式账号及写入开关。

- 派单策略单元测试7项通过：跨区共同授权、无交集、失效选择、缺记录、缺区域、终结/复核状态等；也保留T04超过十人和单区选择覆盖。
- `verify-batch-dispatch-ui.mjs`：实际创建仅A区、仅B区、共同授权3个临时账号，以及两组双区域工单。
- 正常批量：真实界面勾选两区域工单，候选排除仅A/仅B账号，选择共同执行人后正常派发；后端回读两张工单均为ASSIGNED且执行人一致。
- 权限改变：浏览器选中共同人选后，通过真实后端撤销其B区授权，再提交同一批工单；服务器返回现有业务错误HTTP400，抽屉、人员和备注保留，成功提示不存在。回读两单均为DRAFT，均不存在ASSIGN事件，证明前一单写入也被事务回滚。
- 冲突反馈：仅对下一次批量POST注入409业务错误响应，核对已选人员和备注仍在、没有成功提示。这是可控前端错误样本，不伪称服务器真实产生409。
- 无共同候选：重新加载实际已变更的授权后，批量入口显示拆批提示，候选为0，提交禁用。
- 上述浏览器过程没有页面脚本异常，没有force点击、CSS隐藏或DOM修改。
- 原正式单张工单全流程再次通过：派发、接单、开始、上传图片、提交、复核、巡检员刷新回读COMPLETED，页面异常0。
