# T02｜网页展示与统计契约

状态：T01基线及主代理源码复核通过，T02文档任务完成；本文件不表示下列目标展示已经实现。适用于后续T04–T14。当前事实和目标口径分别列出，不能把建议当成已有接口。

## 1. 统一授权与范围

- 服务器角色为ADMIN、MANAGER、INSPECTOR。管理员可访问全部业务区域；值班长与巡检员限授权区域；工单与巡检任务还受执行人/参与人规则限制。
- 只读、主管是网页视图，不是新增服务器角色。切换视图不能扩大权限；只读视图不暴露写操作。
- 全局区域、当前页面筛选、报表区域和个人任务范围必须明确区分。数量入口与目标列表使用同一范围，不允许区域节点卡片旁混入其他区域工单数。
- 全局待办不能复用默认30天报表冒充“全部尚未处理”；创建于30天之前但未结束的工单仍需进入待办。
- 列表加载成功且结果为空时显示“暂无”；请求失败、尚未请求和无权限分别提示，不能都显示0。

## 2. 当前接口事实与展示目标

接口前缀均为 `/api/business`。现有数组返回没有完整总数或截断标记。下表的上限是服务端上限，不是完整业务量。

| 展示对象 | 当前来源、范围和上限 | 目标口径与缺失策略 |
| --- | --- | --- |
| 节点总数/在线数 | `GET /nodes`，返回授权节点，当前无列表上限；每节点包含各指标最新读数、`last_seen`和未恢复告警数 | 在当前区域节点集合统计。维护、停用、无数据、离线独立标示；在线不等于健康。无授权节点显示“暂无授权节点”，不写“稳定运行” |
| 活动告警 | 节点的`active_alarms`在数据库直接统计`recovered_at IS NULL`；`GET /alarms`只返回最新500条授权告警 | 计数应来自未恢复告警的全量聚合；已确认但未恢复仍是活动告警。不能用最新500条过滤后声称完整数量 |
| 今日告警 | 当前首页从最新500条告警中过滤浏览器本地日期和当前区域 | 目标按Asia/Shanghai当天区间聚合，统计触发次数，含当日已恢复记录；与活动告警分开。没有全量聚合前注明“最近记录中的今日告警” |
| 待派单 | `GET /orders`，最新500条；管理员全部、值班长授权区域、巡检员本人主执行或参与且区域授权 | 仅`DRAFT`。`ASSIGNED`单列“待接单”，不能计入待派单。超过列表上限时需要独立聚合 |
| 处理中/待复核 | 同上；详情返回参与人、事件、附件 | 处理中为`ACCEPTED + PROCESSING`，待复核为`REVIEW`。终结态`COMPLETED/CANCELLED`不计待办。本人任务不得等于区域所有工单 |
| 逾期/即将到期 | 报表`overdue`统计时间范围内创建且截止时间早于数据库当前时间的非终结工单；页面部分逻辑只检查`ASSIGNED` | 逾期：任一非终结态且有截止时间、已过期。即将到期：未逾期且在明确提示窗口内，两者不能混称。没有截止时间显示“未设置” |
| 巡检任务/点位 | `GET /patrol/runs`最新300次；按区域及本人执行人过滤；详情返回所有点位 | 未开始`PENDING`、进行中`PROCESSING`、完成`COMPLETED`；点位完成以`checked_at`为准，不用任务列表长度代替点位数。未提交结果显示“待检查” |
| 未读消息 | `GET /notifications`仅当前用户最新200条；网页还应用通知偏好过滤 | 当前只能称“最近消息未读”。完整未读总数需要独立计数；消息偏好影响提示方式，不应静默造成“全部未读”的假象 |
| 审计 | `GET /audit`最新1000条；管理员全部，值班长本人操作或授权区域日志 | 筛选和导出当前加载范围需明确标识。找不到历史业务对象时保留原对象ID，不猜测对象名称 |
| 历史曲线 | `GET /nodes/{id}/history`，采集时间过滤、最大30天、最多5000条，倒序数组 | 时间轴按真实`collected_at`分布；指标分量纲，缺测断线；接近上限提示可能截断，完整导出/分页需另加契约 |
| 人员候选 | `GET /users`为管理员/值班长返回全员及授权区域，目前无分页；派单接口校验启用、巡检员、区域 | 单单按区域交集过滤；批量须满足每张工单。支持搜索完整候选，移除前十人截断。不具备完整任务量时取消智能排序承诺 |

### 当前报表口径

`GET /statistics`及`GET /reports`只允许ADMIN/MANAGER，区域授权在服务器执行。默认最近30天，允许1秒至366天。

| 字段 | 当前真实计算 | 允许的标签/注意事项 |
| --- | --- | --- |
| `orders` | 按工单创建时间范围、当前状态分组计数，无500条截断 | “所选期间创建的工单当前状态”；不能称期间发生的状态变更次数 |
| `alarms` | 按告警触发时间范围、级别分组 | “所选期间告警次数”；不是节点数，也不是当前未恢复数 |
| `averageResponseSeconds` | 所选期间创建工单，从创建到每次ACCEPT事件的时差平均 | 只能叫“平均接单响应时间”，没有现场到场证据。改派后多次接单可能重复计入；目标需明确首个接单事件再去重 |
| `coverage.total/checked` | 所选期间创建巡检任务中的点位结果总数/已填写结果数 | “巡检点位完成率”；按点次计算，不是唯一节点覆盖率。分母0显示“—”，不是100% |
| `alarmRecovery.total/recovered` | 所选期间触发告警总数/当前已恢复数 | “告警恢复率”；已确认不等于已恢复，不等于工单完成率 |
| `monthlyAlarms` | 上海本月首日零点起的授权告警数，不使用报表from/to | 标为“本月告警”，明确与报表时间范围独立；当前没有未来上界过滤 |
| `weekly` | 以to所在上海周为末周，向前12周；分子是各周任务中去重计划节点/已检查节点；分母为当前启用节点数 | 是按当前启用节点计算的计划/检查节点覆盖率，不是任务完成率；与from不完全一致，历史启停变化会影响分母。需显示实际周日期，不能只有W1–W12 |
| `repeatNodes` | 所选期间按节点编号统计多次告警，按次数排序 | “重复告警节点”；不是模型风险分数 |
| 报表导出 | 最多10000条，超过则返回明确错误 | 不能静默截断；缩小范围后重试 |

## 3. 时间、来源和状态语义

### 时间

- `collected_at`：业务采集时间，写库前规范到秒；历史与最新指标以它排序。
- `received_at`：Java服务器写入该读数时的接收时间，不能冒充采集时间。
- `last_seen`：节点已入库的最大采集时间，并非最后HTTP请求到达时间。旧采样入库不将它倒退；不能标成“刚收到消息”。
- 采集桥`receivedAt`：电脑收到串口/Wi-Fi帧的时间；当前候选业务上报用它作为`collectedAt`，`timeQuality=receiver_timestamp`，必须标记“采集桥接收时间”，不能声称设备UTC已校准。
- 页面`lastUpdate`：客户端成功拉取页面数据的时间，只能称“页面刷新于”。刷新一次不能让旧采样变成新数据。
- 告警`triggered_at/recovered_at/acknowledged_at`、工单事件时间、点位`checked_at`为不同业务事件时间，不相互替代。
- 展示明确时区，业务“今日/本月/周”统一Asia/Shanghai。客户端时区与服务器时钟偏差不得改变统计范围；非法或缺失时间显示“时间未知”。

### 来源

| 当前来源/证据 | 目标标签 |
| --- | --- |
| `SIMULATOR` | 平台模拟；不显示为现场实测 |
| `ESP32_DHT11_USB` / `ESP32_DHT11_WIFI` | 设备温湿度实测，经USB/Wi-Fi采集桥；采样时钟质量另标 |
| `ESP32_CH4_DEMO_USB` / `ESP32_CH4_DEMO_WIFI` | 设备生成的模拟甲烷；主控上报不等于实测 |
| 华为IoT适配来源及已核对reported映射 | “华为IoT上报”；只有真实测量来源有证据时才标实测，不能因平台名称而推断 |
| 任意其他、缺失或不能确认来源 | “来源待确认”；保留原始source供详情核对 |

节点`platform`是配置，不是每条读数的来源。来源按指标逐条判断，温湿度实测与甲烷模拟可以同时存在于同一节点。

**当前源码纠偏**：采集桥已生成独立的模拟甲烷报文，网页硬件面板会与温湿度报文一起POST并回读核对。旧文档“甲烷仅预览不入库”已经不能描述当前源码。当前来源标签将`ESP32_CH4_DEMO_*`显示为“主控上报”，T09须保留模拟性质；不能仅隐藏`SIMULATOR`就认为其余都实测。

### 状态

- 节点主状态优先级沿用现有规则：停用、维护、无数据、离线、告警、正常。维护状态不能被理解为已验证在线；同时在详情保留读数时效和活动告警。
- 无数据：从未有有效`last_seen`或目标指标不存在。离线：有历史采样，但超过节点上报周期三倍；历史值可保留，必须标“历史/已过期”。
- “无活动告警”不等于“现场安全”。无阈值规则、无甲烷实测、部分指标缺失均应独立提示。
- 告警确认与恢复正交：确认表示人员已知悉；恢复表示指标/离线条件解除。工单完成不自动证明告警恢复。
- 缺失、非法数值、未知来源和断网不能转成0或伪造正常状态。当前健康分为前端经验公式，未有校准/模型证据，真实业务不宜标成权威健康评分。

## 4. 图表与异常反馈

- 图表每条曲线有名称、单位、来源、实际采集时间；温度不应被强裁到0–100百分比轴。
- 阈值从当前区域配置读取；缺规则显示“未配置”，不套用演示默认值。持续异常条件与瞬时越线不同，说明持续时间。
- 缺测或过期区间断线；无历史显示空态，不能从0绘制趋势。装饰曲线不能承担真实趋势含义，需去除或明确标装饰。
- 当前周图对数字数组推算`completed = planned - 13`属于兼容演示分支，真实报表不能使用；缺字段显示未知，不能造出完成率。
- 首次加载、刷新中、已有旧值刷新失败、无权限、服务不可用分别处理。失败保留用户输入；写入超时先核对服务端结果，不直接重复提交。
- 错误显示可操作下一步，成功提示必须对应服务端成功；提交成功但刷新失败分别说明。

## 5. 后续最小扩展需求（未实施）

1. **待办聚合**：增加统一区域/角色作用域、服务器时间及状态分组计数；包含待派、待接、处理中、待复核、逾期、明确窗口的即将到期、巡检待办。覆盖全量未终结记录，不套用30天创建范围；巡检员只算本人任务。
2. **列表完整性**：需要完整待办时增加同口径服务端筛选/分页，返回`total`、分页参数或明确`hasMore`；不能以500条数组包装前端分页冒充全量。若当期不扩展则明确“最近记录”，不显示全量承诺。
3. **告警与未读全量计数**：按授权聚合当前活动、上海当日触发以及当前用户未读。告警列表应支持按稳定ID访问，避免通知引用的告警已不在最新500条时误判级别。
4. **时间与来源质量**：现有时间和source足以先做保守展示；需要权威设备采集时间、校时质量或实测凭证时再扩展明确字段，不能从来源名字猜测。已有未知source须向后兼容。
5. **异常详情关联**：工单已有`alarm_id`及事件/附件，无需另建事件引擎；告警侧需要稳定详情及按告警ID查询关联工单。历史告警阈值快照当前缺失，应显示“当前规则”并保留原始告警原因，不能冒充触发时快照。
6. **报表含义修正**：先纠正文案；首个ACCEPT去重、实际周起止、历史分母等口径变更另补契约与回归，不在前端伪造新统计。

## 6. 验收样本

- 多区域、各状态工单，含30天前创建仍未结束工单；超过500条工单、500条告警、300次巡检和200条通知。
- 节点无上报、单指标缺失、离线、维护、停用、未配置规则；迟到采样和刷新失败。
- 同节点实测温湿度、模拟甲烷、平台模拟及未知source；服务器与浏览器时区不同、非法时间。
- 工单接单后改派再接单；告警已确认未恢复、已恢复但工单未结束；分母为0、无周数据和超过导出上限。
- 计数点击进入的列表在同一作用域下可逐条对应。缺少扩展接口时仅验收保守文案，不宣称全量任务中心完成。
