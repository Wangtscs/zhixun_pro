## 请求契约

| 参数 | 默认与限制 | 含义 |
| --- | --- | --- |
| areaId | 可省略；提供时必须为正整数 | 指定区域，非管理员仍须有该区域授权；省略则取全部授权区域 |
| queue | 管理者默认unassigned，巡检员默认assigned | 必须属于当前角色允许的队列 |
| limit | 默认20，范围1至100 | 选定队列单页条数 |
| offset | 默认0，非负整数 | 选定队列起始位置 |

未知队列及非法分页返回400；有效但当前角色不可访问的队列返回403；指定未授权区域返回403；未登录返回401。

## 响应契约

业务响应沿用 `code/message/data`。

- `data.scope.role`：服务器真实角色。
- `data.scope.areaId`：请求选定区域，未选定时为空。
- `data.scope.areaIds`：本次范围中实际授权的区域ID。
- `data.scope.personal`：巡检员为true，管理员与值班长为false。
- `data.serverTime`：本次请求捕获的服务器UTC时刻；逾期判断统一使用该时刻。
- `data.counts`：当前角色各允许队列的全历史精确数量，不受旧列表500/300条上限或报表默认30天范围限制。
- `data.queue.key/total/items/hasMore/limit/offset`：选定队列分页结果。total与counts中的同名队列使用相同授权、状态和时间谓词。

同一请求使用REPEATABLE_READ事务和统一服务器时钟。事务不能只读，因为现有会话校验会刷新用户活动时间。分页按截止时间和ID稳定排序；没有截止时间的工单排在有截止时间工单之后。告警按触发时间、巡检按创建时间排序，并以ID消除同时间不稳定性。跨请求仍可能有新增、处置或授权变化，网页应刷新当前队列，不能将offset分页视为跨请求静态快照。

## 队列口径

| key | 可用角色 | 谓词与权限 |
| --- | --- | --- |
| urgentAlarms | ADMIN/MANAGER | HIGH且recovered_at为空；已确认但未恢复仍属于活动紧急告警；受区域权限约束 |
| unassigned | ADMIN/MANAGER | DRAFT工单，受区域权限约束 |
| review | ADMIN/MANAGER | REVIEW工单，受区域权限约束 |
| overdue | 所有真实角色 | due_at早于serverTime且状态不是COMPLETED/CANCELLED；巡检员还必须为主执行或参与人 |
| assigned | INSPECTOR | ASSIGNED工单，授权区域且本人主执行或参与 |
| processing | INSPECTOR | ACCEPTED/PROCESSING工单，授权区域且本人主执行或参与 |
| patrol | 所有真实角色 | 未COMPLETED的巡检任务；管理员所有区域、值班长授权区域，巡检员授权区域且本人执行 |

队列存在重叠，例如待复核工单也可能逾期，**不能将counts各项直接相加为总待办**。无区域授权时返回空scope与零计数，不能回退全局范围。巡检计划停用不自动抹掉已生成但未完成的任务，与现有任务详情权限一致。

## 网页接入要求

1. 首页数字和点击后的队列列表都调用本接口，保留同一areaId及queue，不跳回仍有截断的旧列表来声称展示全部。
2. 用queue.items显示分页，依据hasMore继续读取；total来自服务器，不用当前数组长度覆盖。
3. 工单和巡检项用已有业务ID打开现有详情。urgentAlarms包含node_id、code与区域、位置，供节点／告警详情定位。
4. 角色切换、区域变化、会话退出和过期响应需清理旧队列。只读视图仍不能触发写操作。
5. 网络错误保留已有数据但显示失败与更新时间，不展示虚假零计数。
