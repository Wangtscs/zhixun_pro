# Java API隔离基线与展示契约

日期：2026-11-20。用途：源码基线验证、T01现状依据及T02展示口径输入。本文不代表MySQL、真实设备或鸿蒙真机验收通过。

## 验证环境与隔离

- JDK：21.0.8；Maven：3.9.8；项目编译目标Java 17。
- 本机用户Maven配置中的活动profile设置Java 1.8，覆盖项目声明。因此本轮命令显式传入 `-Dmaven.compiler.release=17`，不修改用户全局配置。
- 保持项目原有依赖版本，联网下载此前未缓存的依赖后执行测试，没有降级Spring Boot或MyBatis版本。
- 所有Spring测试使用local/H2，清空外部配置导入；IoT测试使用StubCloud或MockRestServiceServer。
- 交互验收服务仅监听 `127.0.0.1:18081`，数据库为 `jdbc:h2:mem:website_acceptance;MODE=MySQL;DB_CLOSE_DELAY=-1;DATABASE_TO_LOWER=TRUE`。
- 启动参数明确设置 `spring.config.import=`、`spring.profiles.active=local`、H2驱动、用户名sa及空数据库密码，并禁用IoT；附件目录隔离到被Git忽略的验收运行目录。
- 仅创建合成测试账号。外部MySQL配置、真实账号、云平台Token和设备均不用于本轮验证。
- 内存服务停止即丢失测试数据；本轮服务启动不是生产部署，也不能作为其他机器已经具备相同环境的证明。

## 基线缺陷与修复

原28项JUnit运行结果为20通过、1失败、7错误。公共插入方法使用 `RETURN_GENERATED_KEYS` 时，H2会同时返回自增ID与默认时间戳，`GeneratedKeyHolder.getKey()`因多列结果抛错。创建工单及IoT测试准备账号因此失败。

GitNexus将该公共方法影响面标为CRITICAL：创建管廊、区段、工单、巡检计划、巡检任务生成和异常转工单均调用它。修复仅要求驱动返回 `id` 列；保持方法签名、业务SQL、权限和状态机不变。

新增可由Surefire自动收录的5项JUnit，保留历史独立Regression入口。新测试覆盖驱动列名差异、MySQL无符号数值、缺失键、歧义键、含默认时间戳的真实H2插入、外键关联与事务回滚。含默认时间戳测试先复现失败，修复后通过。

修复后执行：`mvn --no-transfer-progress test package -Dmaven.compiler.release=17`，并显式覆盖外部导入与H2配置。结果：**33项测试全部通过，0失败、0错误、0跳过；可执行JAR打包成功。**

## 权限与角色契约

| 角色或视图 | 当前API行为 | 展示要求 |
| --- | --- | --- |
| ADMIN | 查看全部业务区域；管理账号、区域、管廊；可派单和复核 | 管理视图不能把“当前区域”过滤误解为服务器只授权该区 |
| MANAGER | 业务数据与写入受user_area约束；可维护授权区节点、规则、计划，派单与复核 | 待办、统计、列表和详情必须使用同一授权区域范围 |
| INSPECTOR | 查看授权区节点告警；工单限本人主执行或参与；巡检限本人任务 | 首页以本人可执行任务为主，不能仅按区域统计为本人任务 |
| readonly | 前端视图模式，服务器没有第四种角色 | 隐藏或禁用写操作；不能据此认为后端角色已经变更 |

每次业务请求验证数据库中的启用状态、角色、区域和新会话有效性。新会话包含撤销、过期与无操作超时；旧无jti令牌保留历史兼容过期行为。

## 工单与巡检契约

- 工单主路径：DRAFT、ASSIGNED、ACCEPTED、PROCESSING、REVIEW、COMPLETED。
- REVIEW可退回PROCESSING；未结束工单可由管理者取消；COMPLETED和CANCELLED不再变更。
- 派单要求启用的INSPECTOR，并授权该工单区域；最多两位执行人，共享一份工单状态，不是各自独立完成。
- 批量派单逐张执行相同服务端校验并处于事务内；任一失败整体回滚，前端不能展示为部分成功。
- 提交处理结果只能发生在PROCESSING；复核通过只能发生在REVIEW，且不能由主执行人自行复核。
- 巡检任务按计划复制检查点；未全部完成为PENDING或PROCESSING，全部点提交后COMPLETED。
- 每个点位只能提交一次；只能由该任务执行人提交。异常结果在提交事务内创建DRAFT工单并保存关联ID。
- 真实写入超时应刷新核对，不能自动重复提交。工单创建当前无客户端幂等键，不能承诺未知结果下重试无重复。

## 数据来源、时间与节点状态

- 监测记录区分source、collected_at与received_at。collected_at为采集时间，按秒规范化；received_at为服务器接收时间。
- 迟到数据可进入历史，但不逆转实时告警。节点、消息ID和指标联合去重。
- 当前支持甲烷、温度、湿度、红外指标；显示对应记录unit，不以名称猜单位。
- 模拟与实测由明确来源判断；未知来源显示未知，不推断为实测。网桥温湿度为实测，模拟甲烷不因单位相同而成为真实甲烷测量。
- 节点展示优先区分停用、维护、无数据、离线、告警、正常。超过节点上报周期三倍未更新为离线；无上报记录为无数据。
- 活动告警依据recovered_at为空，不应只检查是否人工确认。人工确认不等于指标恢复。
- 接口刷新失败仍可保留旧数据，但必须显示失败和更新时间，不能继续声称已实时更新。

## 统计与分页口径

| 数据 | 当前API范围 | 不能直接承诺的行为 |
| --- | --- | --- |
| 工单列表 | 最近500条；含角色及区域权限 | 列表内数量不等于所有历史待办总数 |
| 告警列表 | 最近500条；受区域权限 | 不能从截断列表推算完整未恢复告警总数 |
| 巡检任务列表 | 最近300次；受区域和执行人权限 | 不能当作全部历史任务统计 |
| 通知 | 当前用户最近200条 | 返回条数不等于全量未读数 |
| 操作审计 | 最近1000条；管理员全部，值班长本人及授权区 | 不代表无限历史查询 |
| 监测历史 | 最大30天、最多5000条 | 不承诺查询范围内采样全部返回 |
| statistics | 默认最近30天；支持1秒至366天；按创建或触发时间筛选 | 历史创建的未结工单可能不在近期统计内，不能作为全量待办接口 |
| reports | 按指定类型、区域、时间，最多10000条；超限报错 | 不能静默截断后提示导出完整 |

统计具体含义：工单按创建时间分状态；告警按触发时间分级；逾期为上述工单范围内due_at已过且未完成/取消。平均响应时间从工单创建至ACCEPT事件，不等于实地到场时间。巡检coverage为范围内任务检查点已提交数/总数，不等于独立节点覆盖率。alarmRecovery按recovered_at统计恢复；monthlyAlarms以本月起点为准，独立于自定义起止范围。weekly为按周去重节点占当前启用节点数量的比例，不是逐任务完成率。

T10若展示全量待办，应增加服务端精确聚合契约；不能将现有截断列表或默认30天统计改名为“全部待办”。
