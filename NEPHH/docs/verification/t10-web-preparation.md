# T10网页任务台接入准备

状态：独立组件与演示分支已准备；尚未集成正式首页，也未执行真实API浏览器联调。T10未完成验收。

## 组件契约

`WorkbenchPanel.vue` 输入 `areaId:string`、服务器真实 `role:string`、`readonly:boolean`。向父级发出 `openOrder(id)`、`openPatrol(id)`、`openNode(id)`、`space()`；组件自身只读，不新增派单或复核写接口。

- 管理者队列：紧急告警、待派单、待复核、逾期和巡检待办。
- 巡检员队列：待接单、处理中、逾期、本人巡检待办。
- 数量来自 `/api/business/workbench` 的 `counts`；列表来自同响应的 `queue.items`，每页20项，`total/hasMore`控制翻页。不使用旧500条工单或300次巡检列表，不相加重叠队列。
- 告警暂发出稳定 `node_id` 供T11前节点详情兼容；工单、巡检直接发出业务ID，父级应按ID请求详情，不能只在旧截断列表中查找。
- 15秒独立刷新；隐藏页面不轮询，恢复可见时刷新。区域、角色和只读视图改变时清空快照并重设队列；revision、登录凭据比对和卸载清理拦截过期响应。请求复用既有10秒超时，卸载不再回写状态。
- 同范围刷新失败保留旧快照并明确过期；401/403清除旧数据并显示访问受限；首次加载、尚无角色、零任务、无授权区域、分页被业务变化清空分别提示。
- 时间显式使用上海时区。读数来源和事件性质仍由详情负责，任务数量不隐含现场安全。
- 复用公共 `request` 的网络、演示分流和401处理。新增兼容的 `BusinessRequestError` 仅附加HTTP状态和业务code；原message、Error继承关系及401清会话/跳登录行为保留。

## 演示分支

仅新增 `demoRequest` 的 `GET /workbench` 路径；既有路径和数据不变。队列读取同一内存工单，区域、分页、队列白名单和错误形状与新接口一致。演示身份目前固定MANAGER，不通过额外role参数伪造巡检员权限。现有演示没有巡检任务，巡检队列保持空，不制造无法访问详情的记录。

组件在演示环境显著标出独立虚构数据。演示操作不访问真实API或数据库。
