# T06｜任务工作台设计与原型

状态：T05完成后由主代理用可见Edge完成浏览器试走，T06已验收通过。本文没有真实用户访谈结论，也没有正式页面或接口已完成的声明。

## 目标与约束

面向值班长日常调度、巡检员本人任务及管理者复核。首屏回答“现在该处理什么”，详情回答“依据是什么、下一步由谁做”。保留现有权限、路由和工单状态机；首页重排不新增服务器角色。所有统计遵循T02展示契约，不用截断列表冒充全量。

原型位于根目录 `prototypes/workbench.html`，使用单文件HTML/CSS/JavaScript，无第三方依赖、网络请求和真实账号。所有记录明确为虚构；操作仅修改当前页面内存，刷新或点击重置即恢复。

## 三种方案与取舍

### 方案A：任务优先（默认采用）

入口最小化为任务队列、空间监控与详情。值班长优先看到待派与待复核，巡检员优先看到本人待接和处理中。隐藏后台规则维护及原始字段，以状态动作和可读证据串联业务。

优点是下一步明确，角色范围容易理解；不足是不能在一屏表达所有设备位置和长期趋势。通过空间入口和报表解决，不将它们塞进首页。

### 方案B：空间优先（保留为监控视图）

入口为管廊区段和节点。点击位置查看来源、时间、告警及关联任务，减少先记节点编号再搜索的步骤。隐藏设备协议和接入配置。

空间定位更直观，但坐标必须有依据；调度事项容易分散在不同点位。保留为辅助视图，派单与复核仍使用任务队列。无真实坐标时只能明确标为布局示意。

### 方案C：事件优先（详情层采用）

入口为一次异常的完整记录，将告警、读数、工单、附件与时间线集中。隐藏跨页面查找和关联关系，但保留每条记录的稳定ID。

有利于复核、追溯和交接；自动聚合可能误合并独立风险。因此本轮只做稳定ID关联详情，不创建事件引擎、不自动合并告警。

### 综合决策

默认任务优先，空间图帮助定位，事件式详情集中证据。三者共享作用域和业务ID。相较全功能首页，默认入口更少；相较只做监控大图，完成业务操作更直接。正式实施仍需接口侧全量计数与筛选保障，原型内存样本不替代该能力。

## 页面结构与视觉方向

- 顶部固定显示当前范围、角色预览和主题操作，避免区域筛选散落于不同卡片。
- 左侧文字导航默认展开。图标或编号仅辅助识别，入口无需悬停才知道含义。
- 首屏四个可点击队列：待派单、待接单、处理中、待复核。巡检员隐藏管理派单队列，仅显示本人演示任务。
- 主列为可搜索、可筛逾期的任务列表。优先级、逾期、截止时间和执行人有独立文字；待派仅DRAFT，待接仅ASSIGNED。
- 侧列显示区域节点状态及数据边界，保持低干扰。硬件调试不放在日常主操作区。
- 右侧详情抽屉先显示状态和任务说明，再显示读数来源/时间、关联记录及下一步。关闭恢复焦点，Esc可返回，键盘焦点不离开抽屉。
- 风格为克制的工业工作台。暗色深蓝灰、浅色雾灰，青色标操作，红色标紧急，黄色标模拟或预警；同时用文字表达状态。
- 正文14px、辅助12px，关键数字采用等宽数字；边框和留白组织密度，不用大面积装饰曲线暗示业务趋势。支持减少动态偏好。

## 原型可点击范围

1. 切换值班长、巡检员、只读视图、管理员；范围和队列随角色改变。
2. 切换授权区域、队列，搜索任务，筛选逾期；卡片数量与当前样本范围一致。
3. 点击任务查看详情；值班长试走派单/复核，巡检员试走接单、开始、填写结果与提交复核，只读没有写入口。
4. 打开空间视图，点击不同节点查看状态、虚构样本和关联任务；从任务可定位空间，从节点可进入任务详情。
5. 切换深浅主题、重置样本；使用Tab导航、Esc关闭、焦点恢复及窄窗口布局。

原型有意不模拟真实上传、API鉴权、并发写入、持久化和服务器审计。测试期间不得输入真实账号或现场敏感数据。
