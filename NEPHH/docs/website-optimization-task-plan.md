# 智巡管廊网页优化任务安排

状态：执行中。当前逐项结果见 `verification/task-status.md`；本文保留任务范围和验收要求，不将整份计划视为已完成。

排期方式：不设日期、工期或日历提醒；以优先级、前置依赖和验收结果推进。负责人仅指定职责，由团队落实具体人员。

## Problem Statement｜问题与目标

当前网页已有监测、告警、工单、巡检、报表和权限功能，但日常处置入口分散，角色待办不够突出。派单候选列表没有按工单区域筛选且截断前十人；数据来源、时效和异常上下文需要更清楚地呈现。界面存在小字号、图标导航依赖悬停、图表量纲和时间表达不充分等问题。

优化目标：让用户清楚知道下一项工作，顺利完成处置，并正确判断数据的来源和时效。优先改善现有闭环，不新增未经验证的预测能力。

阅读依据为当前源码和主要文档；尚未完成浏览器视觉复验及用户访谈，视觉判断和任务优先级须在实施前用原型验证。没有可支撑量化收益的行为数据，不填写虚构的机会分数或提升百分比。

## Solution｜方案

默认采用任务优先工作台。值班长优先看到区域待办，巡检员看到本人任务，管理员保留配置维护入口。空间视图继续承担定位和监控；现有详情抽屉集中展示异常证据与关联记录。

三个优先机会：

| 机会 | 影响与投入判断 | 首选方案与替代方案 | 高风险假设及最小验证 |
| --- | --- | --- | --- |
| 找得到合法执行人 | 高影响、低至中投入；涉及批量派单边界 | 区域过滤并支持全量搜索；备选为独立人员选择弹窗 | 多区域批量工单是否需要共同执行人。用区域不重叠工单验证，不能满足时要求拆批 |
| 找得到下一项工作 | 高影响、中投入；依赖角色和统计口径 | 角色待办工作台；备选为仅重排当前首页模块 | 用户是否以待办为主要入口。让值班长与巡检员分别用可点击原型找任务，记录误点和查找路径 |
| 看得懂异常依据 | 高影响、中投入；受接口字段限制 | 补齐来源、时间、状态并串联详情；备选为先增加关联入口 | 已有字段能否说明新鲜度和来源。用实测、模拟、离线、缺数、恢复样本核对 |

## Decision Document｜实施决策

- 范围以网页端体验和必要的兼容接口调整为主。移动端独立任务不混入本轮。
- 默认首页采用任务优先。空间视图保留为监控入口；事件信息先通过已有详情关联呈现，不新建独立事件引擎。
- 角色与区域权限继续由服务器裁决；前端菜单和过滤仅帮助正确操作，不能替代鉴权。
- 单单候选按工单区域筛选；批量候选必须同时满足每张工单的授权区域要求。不可满足时要求拆批，不放宽权限。
- 首版不承诺智能推荐排名。若没有完整任务量数据，使用透明排序并取消“按任务量推荐”的误导文案。
- 默认保持业务状态机和数据库结构；统计、关联或完整候选所需字段不足时，先明确契约，再最小化扩展。任何迁移单独评审和验证。
- 待办统计与详情列表使用一致的授权、时间和状态口径。列表截断与统计总数明确区分。
- 实测、模拟、未知来源分别展示。采集时间与接收时间不混用；离线不代表读数为零。
- AI 内容作为待人工核实的建议，不能伪装为传感器事实、已验证预测或自动完成的处置。
- 保留深浅主题及现有业务地址。统一可读性与状态表达，不以增加装饰动效为交付目标。
- 基础组件提取只服务本轮真实需求；不先重写整个工作台，也不为假设中的未来功能搭建通用平台。

## Testing Decisions｜测试与验收

好测试应验证用户可观察行为、权限边界和业务结果，而非组件内部变量或实现结构。低影响样式调整用针对性视觉核对；权限、派单、统计和写入异常必须覆盖行为测试。

### 当前基础与限制

- 网页已有通知策略、模拟数据单元测试；上一轮7项通过，类型检查通过。这不是本计划实施后的结果。
- 现有浏览器脚本有旧选择器，需要先修复；不能直接引用旧验收结论。
- Java 已有H2隔离测试和业务验证脚本；上一轮离线运行被缺失依赖阻断，尚未执行测试。实施时先解决依赖并验证隔离配置。
- 验证脚本会创建数据，应只对专用测试库执行。构建、类型检查、单元测试和真实业务验收分别记录。

### 必验行为

1. **选人**：超过十名巡检员、跨区人员、禁用人员、区域无候选、多区域批量工单、已选人员随后被禁用。
2. **权限**：管理员、值班长、巡检员、只读视图；前端改地址和直接发请求均不能越权。
3. **统计**：待办数量与目标筛选一致；超过现有列表上限仍不显示误导性总数；无数据、部分失败有独立提示。
4. **监测**：实测、模拟、未知来源；陈旧、离线、缺数、迟到上报、刷新失败；不同采样周期与不同量纲。
5. **闭环**：告警关联工单、派发、接单、开始、提交、退回、重新提交、通过；检查状态与时间线一致。
6. **并发及网络**：连点、多人操作、提交超时、提交成功但刷新失败；不假报成功，不盲目重复写入。
7. **硬件**：调试入口移动前后读写语义一致；导航、断网和停止上报不会造成隐蔽上报或缓存冒充新数据。
8. **可用性**：双主题、键盘焦点、无悬停导航、弹窗滚动与关闭、主要窗口尺寸、错误与空态；状态无需仅靠颜色识别。
9. **用户试走**：让值班长找到并派发紧急事项，让巡检员找到本人任务，让复核人员找到结果证据。记录完成情况和卡点，不预设提升比例。

### 完成证据

每项任务保留：实现版本、验证环境、操作步骤或自动化结果、关键截图、已知限制。T15验证通过后才进入T16；未通过的任务继续标记待修复，不以文档补写代替功能完成。

## Out of Scope｜本轮范围外

- 鸿蒙端静态通知、演示设置和找回密码接入，另建移动端任务。
- 双Agent、RAG知识库、风险预测、自动派单和现场设备控制。
- 自动合并告警的事件引擎、离线同步、新账号体系或新服务器角色。
- 华为IoTDA生产联调、云端部署、硬件采购与固件改造。
- 大规模技术栈替换、无业务必要的数据库重构和全站重写。
- 数据库明文默认凭据整改应作为独立安全任务优先跟踪，不因本计划未包含而视为已解决。
