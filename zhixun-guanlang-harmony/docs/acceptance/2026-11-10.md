## 已覆盖但不能判为通过的界面

- A/B/C 列表、9 个节点详情、3 个透视场景、两类助手问答、个人中心与深浅主题都有对应原生组件。DemoRepository 的节点 ID 和主要读数可与原型对应；这不证明图表折线、布局、字体和安全区一致。
- 列表历史截图可见卡片尺度、分栏与间距不同；不使用带模拟器机身和工具栏的截图计算像素相似度。节点详情、透视与助手的新截图尚缺。
- 浅色组件普遍读取 darkMode，但告警色、背景透明色和透视 SVG 仍需在浅色实际屏幕验证；不能由深色通过推导浅色通过。
- 扫码、企业微信在原型本身就是演示说明抽屉，不把没有真实扫码/企业认证接口计为本轮原型缺陷。原型助手和验证码同样为演示流程。
- 相册原生选择器替代浏览器文件选择器属于平台适配，不直接判为外观缺陷；选图、取消、回显、上限和重新进入仍需设备验证。

## 对上一轮报告的校正

补充核对 Make 事件源码：设置中的“退出登录”和“当前账号”都打开“账号信息”说明抽屉，并不真正退出。应补齐这个入口与抽屉，不能把真正注销账号作为原型已有能力。工单列表固定进度也存在于 Make，N04 已校正为产品一致性问题。核对本地源码不等于已现场点击在线 Make 预览。

1. 编号原型实际为 **140 张**；“142”不符合当前目录与说明文件，不沿用此数量。旧报告中的 Figma 80 状态属于另一种文件口径，本轮不据此缩减检查范围。
2. 找回密码的演示验证码两边都是 **123456**。差异是六格输入、倒计时、错误次数与重发状态，不是验证码值。
3. “用户工单应全部完成才可上报”是可讨论的产品规则，但原型本身允许 2/5 上报。此次严格按原型记作行为差异，不能单方面改变标准。

## 复验条件与顺序

1. 先补齐 N01—N07 的工号、找回、抽屉、工单状态、退出登录和支持入口。
2. 再修正 N08—N15 的反馈、通知、设置、关于、工单版式、风险内容和公共标题/登录视觉。
3. 启动 API 22 手机模拟器或连接鸿蒙手机，重新构建安装，记录 HAP SHA256；按核对表的 140 个状态逐项截图和操作。每条需记录原型、实际、进入步骤、预期/实际结果；无法到达的状态记失败，不能用近似页面代替。
4. 使用 390×844 对应的逻辑内容视口对照，排除模拟器机身、工具栏、指针与系统开孔；再核对深浅主题、底部安全区、键盘遮挡、滚动补充、抽屉关闭和硬件返回。若设备尺寸不同，保留原图并记录缩放方式，不直接算失真的像素差异。
5. 明确的差异修复且所有待复验项有当前版本证据后，才可出具最终“全部界面一致”结论。

**当前结论：不能通过“鸿蒙手机端所有界面与原型一致”的验收。已确认流程、入口、状态及布局差异；全量设备运行验收尚未完成。**
